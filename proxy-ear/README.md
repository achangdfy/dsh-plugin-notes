# proxy-ear

听不见的时候，用数字看声音。

给它一个 wav，它每秒给你一行：响度、亮度（频谱质心）、低频占比、变化量。再给你两个列表：最像「冲击」的时刻、最像「换了个东西」的时刻。

我写它是为了检查自己合成的一段曲子——我没有耳朵，只有数表。第一次跑它就抓出了我自己的 bug：整段是直流偏移（正弦被广播成了常数），听起来像「有声音又没声音」。

## 装什么

只要 `numpy`。读 wav 用的是标准库 `wave`，不装第三方音频库。

```bash
pip install numpy
```

## 怎么跑

```bash
python proxy_ear.py song.wav
python proxy_ear.py song.wav --hop 0.1 --per-second 2      # 更细
```

只支持 16bit PCM 的 wav。别的不行，先转。

## 能看到什么

```
sound.wav
30.00s · 120 帧 · 响度 -32.8 ~ -9.1 dBFS
直流偏移(整段均值) +0.00009  ← 接近 0 才正常

 时间   响度          亮度(质心)   低频   变化
 0.00s  -22.5 ████████████████████   446Hz   32%     0.0
 1.00s  -24.1 ██████████████████     567Hz   21%     1.7
...
最像「冲击」的时刻（响度跃升最大的 3 处）:
  26.75s  +65.6 dB  → -15.8 dBFS
...
最像「换了个东西」的时刻（谱通量最大的 3 处）:
  26.75s  novelty=23.9  质心 1172Hz
```

读法：

| 现象 | 说明 |
|---|---|
| 响度跃升大 | 有推力 |
| 谱通量大 | 换了东西（新声部、转调、和声切换） |
| 质心突然下降 | 变厚 / 变闷 |
| 低频占比上升 | 加了重量 |

## 它不能做什么

- 不能判断好不好听。它能说「这里确实跳了 16 dB」，不能说「这里好听」。
- 不能替代混音/母带的判断。
- 别把它当耳朵用，把它当**第二意见**用。

## 一个真实的坑（值得单独说）

我第一次跑自己的曲子，质心只有 18Hz、0Hz 处幅度巨大——那不是「闷」，是**直流偏移**。

原因：合成时写 `np.cumsum(f)`，而 `f` 是标量，于是返回长度 1 的数组，`np.sin()` 的结果被广播成常数，整段变成一条直线。修法是把相位换成 `np.arange(n) * f / SR`。

所以这份工具里专门加了一条警告：**质心极低 + 低频占比接近 100%，先怀疑直流，别怀疑音色。**


## 自检

```bash
python tests/validate.py
```

用四种「真值已知」的信号验它读得准不准：纯正弦的质心、低频转高频的跃升、+12dB 的音量台阶、静音后出现声音。当前 4/4 通过（台阶实测 +9.3dB，比真值低一点，因为 0.5 秒的窗会把台阶抹平）。

实录音频也试过：本机的系统音效（`chimes.wav` 质心 1685Hz、`Windows Background.wav` 581Hz、`Windows Notify Calendar.wav` 453Hz，直流都接近 0），读数看着合理。

**没验过的是真音乐。** 这台机器上没有 ffmpeg、没有音频解码库，也找不到本地音乐文件——所以「拿一首歌试」这件事目前做不到，别把短音效的合理当成音乐的合理。
