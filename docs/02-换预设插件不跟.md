# 02 · 换了预设，插件就没了

## 现象

你自己写了个插件，profile 里装得好好的，工具也出来了。
然后你把默认预设切成了自己的那一套（想改人设、想加提示词），重启。
**插件全没了。** profile 的 `cordis.patch.yml` 里明明还写着它。

## 为什么会这样

预设不是「一层提示词」，是一整套插件树。
每个预设从自己的根开始拼：它有自己的 `agent.cordis.yml` / `cordis.patch.yml`，自己决定装哪些服务、哪些工具。

profile 层的 patch 属于 profile 的那套装配。切到预设，等于换了一个装配根——你在隔壁房间装的东西，这个房间里没有。

用大白话说：**换预设 = 换一整套家具清单，你在旧清单上加的东西不会跟过来。**

## 还有个更坑的：目录不等于已安装

早一些的版本有人会告诉你「把预设目录丢进 `~/.dsh/.agent-presets/`，再把默认预设改成它」。
在现行版本上这是死路：DSH 只认**已安装 bundle** 里声明的预设，不读那个目录。你改完默认，等于指向一个不存在的定义——开新会话直接失败。

判断方法：看 `package.json` 里有没有 dsh 相关的 `preset` 声明，以及它是不是真的在 `node_modules` 里。

## 怎么修

把插件写进预设自己的 `cordis.patch.yml`：

```yaml
- insert:
    - id: my-plugin
      name: my-plugin
      # 指向本仓库的绝对路径，用 file:// 形式，不动 node_modules
      # 具体条目格式以你那个版本的 include 插件为准
```

两个注意点：

1. **路径要能被解析**（`file://` 加绝对路径最稳），别依赖 `node_modules` 里的软链——`pnpm install` 一次就给你扯没。
2. **它依赖的服务得在那棵树里**。预设树里没有 `tools`，你的工具注册就会静默跳过（见 [01](01-插件不加载.md)）。

## 怎么验证

- 开**新**会话再看。已经跑着的会话不会变——插件树是启动时拼好的。
- 看诊断日志有没有新的一行 `module evaluated`。没有就是没加载，别自己骗自己。

## 回滚

删除你加的那几行（连同注释），保存。不是删文件，所以随时能退。

## 一句教训

**每次切预设，第一件事是数一遍插件。** 我丢过一次，找回来花了一晚上。
