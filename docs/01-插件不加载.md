# 01 · 插件装上了，但是不加载

## 现象

`dev_plugin_status` 里能看到它，状态是 `[no-fiber]`，或者注入日志里写着 `host ✗`。
工具列表里没有你的工具，system prompt 里也没有你注入的段落。它不报错，就是不干活。

这个最恶心：静默失败，没有异常，你会以为是自己的代码写错了。

## 原因 A（最常见）：顶层强依赖

```js
export const inject = ['tools']   // ← 凶手
export function apply(ctx) { ... }
```

`export const inject` 是「我要这个服务，没有就别加载我」。
但插件的加载位置不一定是根上下文——比如它被放进某个预设的插件树里，那里的上下文可能还没有 `tools`。于是整个插件被静默跳过。

**改法：声明式换成过程式。**

```js
export function apply(ctx) {
  ctx.inject(['tools'], (ctx) => {
    ctx.effect(() => ctx.tools.register({ /* ... */ }), 'my tool')
  })
}
```

`ctx.inject` 的意思是「这个服务出现了，再执行这段」。根上下文能用，预设树里也能用。服务晚一点出现也没关系。

## 原因 B：junction 建在了错的 profile

用注入器链接本地插件目录时，它默认往 `~/.dsh/profiles/web/node_modules` 建链接。
但你跑的可能是 `desktop`（或者别的 profile）。链在一个房间、人在另一个房间，喊破嗓子也没人应。

**怎么确认**：看 DSH 启动时的 profile，或者看 `~/.dsh/profiles/` 下哪一个有正在更新的日志。

**改法**：在正确的 profile 目录下自己建一个 junction（目录符号链接也行）。

```
mklink /J "C:\Users\<你>\.dsh\profiles\desktop\node_modules\my-plugin" "D:\path\to\my-plugin"
```

## 原因 C：入口对不上

`package.json` 的 `main` 指向的文件不存在，或者写成 CommonJS 但包声明了 `"type": "module"`。
这种情况不是静默的，日志里会有 import 失败——但日志藏得深，容易漏看。

## 排查顺序（照这个走，别乱试）

1. 看注入器的诊断日志，确认 `module evaluated` 和 `apply` 有没有打出来。
2. 有 `apply` 没效果 → 原因 A。
3. 连 `module evaluated` 都没有 → 原因 B 或 C。
4. 都正常但还是没工具 → 看看你那层的 `ctx.tools` 是不是另一个实例（少见，但在我这台机器上出现过一次）。

## 我实测的一次（2026-10-25）

同一台机器上，同一个骨架：

1. 直接注入 → `host ✗`，工具没出现。
2. 看目录：注入器把 junction 建在 `profiles/web/node_modules/`，而我跑的是 `desktop`。
3. 手工在 `profiles/desktop/node_modules/` 建了一个 junction → 重新注入 → `host ✓`，工具当场出现，调用返回正常。

**注意一个反直觉的地方**：第二次注入时，注入器的返回信息里仍然写着 `junction=C:\...\profiles\web\node_modules\...`。
也就是说——**它报告的路径不等于生效的路径**。真正起作用的是我手建的那个 desktop 链接。

所以别把注入器的提示当成结论，去看工具到底出没出来。

## 一句教训

**静默失败优先怀疑「加载位置」，别怀疑自己的业务代码。**
