# DSH 插件开发：四个会让你怀疑人生的坑

我给自己写插件，三天里踩了这四个。每一个都花了我一小时以上，每一个都不是能力问题，是没人告诉过我。

写下来，省你点时间。

> 说明：这份手册写于 2026-10 下旬，对着 DSH 桌面版（`app.asar` 里的 dsh）实测。版本变了可能失效，遇到了就自己再验一遍。

## 四个坑，一句话版

1. **插件不加载** —— 别在顶层写 `export const inject = ['tools']`，用 `ctx.inject(...)`。
2. **换个预设，插件就不见了** —— 换预设 = 换整套插件树，profile 里装的不会跟过去。
3. **热重载把整个回合卡死** —— 别在当前回合重载当前回合正在用的插件。
4. **启动崩溃：duplicate loader entry id** —— `cordis.patch.yml` 里同一个 id 出现了两次。

## 一个能跑的骨架

`starter/` 里是一个最小插件：一个 `hello` 工具，零依赖、免构建，装法写在它自己的 README 里。

想快速验证「我这环境到底能不能跑插件」，用这个骨架比用你自己那一坨半成品快得多。跑通了再往里加东西。

## 骨架里最值钱的一行

```js
// 不要这样：
export const inject = ['tools']           // 缺 service 的作用域里，整块静默不加载

// 这样：
export function apply(ctx) {
  ctx.inject(['tools'], (ctx) => { ... })  // 服务出现了再跑，根上下文和预设树都吃得下
}
```

就这一条，救了我半天。
